# 黑话替换清单（写需求前必查）

本清单里的每个词，都是普通人听不懂、或听了也不知所云的"产品黑话"。写 PRD 时，**只要出现就用右边的大白话替换**。

## 必须替换的术语

| 黑话 | 普通人大白话 |
|------|--------------|
| 用户画像 | 这东西主要是给哪类人用的（比如：小区里带娃的家长） |
| 目标用户 | 主要给谁用 |
| MVP | 先做个最简单的能用的版本 |
| 敏捷迭代 | 先做一版，用了再说，慢慢改 |
| 闭环 | 一件事从头到尾都能在这上面办完 |
| 赋能 | 帮用户把这件事办成 |
| 抓手 | 最管用的那个办法 |
| 痛点 | 最让人烦心、最不方便的地方 |
| 颗粒度 | 说得细不细 |
| 护城河 | 别人很难抄走的优势 |
| 飞轮 | 越用越好、自己转起来的循环 |
| 抓手 / 组合拳 | 几件事一起做 |
| 拉通 / 对齐 | 跟相关的人商量好、说一致 |
| 沉淀 | 把经验留下来以后能用 |
| 链路 | 从头到尾的一连串步骤 |
| 触达 | 让用户知道、看到 |
| 转化 | 从看看变成真的用/买 |
| 留存 | 用过的还愿意再来 |
| 平台化 | 做成大家都能来用的公共地方 |
| 中台 | 把大家都要用的事集中管起来 |
| 赋能 B 端 | 帮商家/企业把事办好 |
| 打磨 / 打磨体验 | 把它做得更好用 |
| 漏斗 | 从感兴趣到真用上，一层层少下去的过程 |
| 心智 | 用户在心里对它的印象 |
| 背书 | 有可信的人/机构帮它说话 |
| 护盘 | 保住现有的用户别流失 |
| 生态 | 围绕它的一堆相关服务和人 |
| 私域 | 自己能直接联系到的一群用户（比如微信群） |
| 规模化 | 用的人多了也能撑住 |
| 商业化 | 靠它挣钱 |

## 机器腔句式（也要改）

| 别写 | 改成 |
|------|------|
| 系统应提供 XX 模块 | 我想打开就能 XX |
| 支持 XX 功能 | 我能用它来 XX |
| 具备 XX 能力 | 它能帮我 XX |
| 实现 XX 机制 | 用了之后，XX 这件事就自动解决了 |
| 优化用户体验 | 用起来更顺手了 |
| 提升效率 | 以前要半天，现在几分钟搞定 |

## 自检口子

写完读一遍，问自己："我妈 / 我邻居 / 一个完全外行的人，能看懂每一句吗？"
只要有一句会让人皱眉，就重写。

## AI 友好 ≠ 加黑话

对 AI 友好，不是往文档里塞术语，而是**字段名统一、语义无歧义**：

- "接口定义"四个字段固定叫：入口 / 触发 / 输入参数 / 输出，全篇不漂移。
- "验收标准"每条用可勾选的 `[ ]`，写"用户能做什么 + 预期结果"，不写"体验良好"这种不可验证的话。
- 章节标题与模板保持一致，AI 才能稳定定位模块、抽取功能点与验收条件。
- 通俗语言照写，只是用统一字段把它们框起来——大白话和结构不冲突。
