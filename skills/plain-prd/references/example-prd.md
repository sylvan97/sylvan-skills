# 小区邻里互助 需求说明

> 这是风格示例，仅用于感受大白话的语气和模块结构。实际内容必须基于用户提供的信息来写。

## 产品概述
- 一句话说清楚：一个让同一个小区的人互相帮忙的小工具——谁要借个电钻、谁下班顺路能帮带个快递，发一条消息就有邻居接。
- 给谁用：同一小区的住户，尤其是带娃家长、独居老人、加班族。
- 解决什么麻烦：住一栋楼却互不认识，借个东西、找人帮个小忙得在群里刷屏问、还经常没人理。

## 功能列表
### 功能一：发求助
- 用户想做：我想发一条"我需要帮忙"的消息，写清楚要借啥、在哪、啥时候要，邻居刷到就能应。
- 入口：App 首页 → 大按钮"发求助"
- 输入：求助内容、地点（楼栋）、需要的时间
- 输出：一条求助帖，推送给同小区、距离近的用户

### 功能二：接求助
- 用户想做：我想在小区范围内看大家发的求助，离我近的排前面，点一下"我能帮"就私下跟对方说上话。
- 入口：App 首页 → "附近求助"列表
- 输入：无（浏览）；接单时选"我能帮"
- 输出：进入与发布者的私聊，手机号不直接公开

### 功能三：留好评
- 用户想做：我想看完帮忙后给对方留个好评，以后找人更放心。
- 入口：一次互助结束后 → "评价"入口
- 输入：星级 + 一句评语（可选）
- 输出：对方主页显示好评，提升可信度

## 用户场景
- 场景一：周六上午，李姐想挂幅画，家里没有电钻，又不想为用一次花钱买。她打开工具发"借电钻，今天下午用，3栋"，住在2栋、刚好有电钻的老王看到，顺手就答应了。
- 场景二：周三下雨，小陈加班到九点，快递放驿站要走十分钟还不安全。她在群里发"谁能顺路帮我拿个快递"，同栋下班的邻居顺手带了回来。
- 场景三：张叔儿女不在身边，想找人帮忙搬一下新买的米面。发条消息，楼下的退休邻居刚好空着，约好时间就来搭把手。

## 接口定义
- 功能一：发求助
  - 入口：App 首页 → "发求助"按钮
  - 触发：填写并提交
  - 输入参数：求助标题、内容、楼栋、期望时间
  - 输出：一条求助帖（仅本小区可见），推送给附近用户
- 功能二：接求助
  - 入口：App 首页 → "附近求助"列表
  - 触发：点击"我能帮"
  - 输入参数：无
  - 输出：与发布者建立私聊会话
- 功能三：留好评
  - 入口：互助结束后 → "评价"
  - 触发：点击提交
  - 输入参数：星级（1-5）、评语（可选）
  - 输出：发布者好评数 +1，展示在其主页

## 验收标准
- 功能一：发求助
  - [ ] 用户能填写标题/内容/楼栋/时间并提交，提交后自己能在"我的发布"里看到这条求助
  - [ ] 同小区其他用户能在"附近求助"刷到这条帖，发布者所在楼栋越近排序越靠前
  - [ ] 非本小区用户看不到这条求助
- 功能二：接求助
  - [ ] 用户能点"我能帮"进入私聊，且整个过程不暴露双方手机号
  - [ ] 发布者能收到"有人想帮你"的提醒
- 功能三：留好评
  - [ ] 一次互助结束后双方都能给对方评星，评星后主页好评数实时更新
  - [ ] 未结束的互助不能提前评价

## 大家最在意的几点
- 好不好上手：界面就一个大按钮"发求助"，老人家也会点。
- 收不收费：基础互助免费，不收会员费。
- 安不安全 / 隐私咋办：只能本小区看到，手机号不公开，聊天才给；有过往好评的人更可信。

## 出问题了怎么办
- 用户最怕在什么环节出岔子：发了求助没人理、或接单后对方失联。
- 网络断了怎么办：发求助时断网，本地先存草稿，恢复后自动重发并提示"已发出"。
- 输错了 / 找不到入口怎么办：求助发错楼栋，允许发布后 5 分钟内自己删掉重发；首页一直有"发求助"大按钮，不会找不到。
