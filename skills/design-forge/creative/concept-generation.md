# Concept Generation Protocol

Generate concepts before generating UI.

## Required output

For a sufficiently open-ended design task, generate **3–5 genuinely different concepts**. Use fewer only when the problem is tightly constrained and explain why.

Each candidate must differ in at least three structural dimensions, not merely visual styling.

## Concept dimensions

Explore combinations of:

- **Mental model:** archive, instrument, map, magazine, stage, workshop, library, playground, field notebook, timeline, observatory, dashboard, collection, etc.
- **Navigation:** index, spatial discovery, narrative scroll, command/search, contextual reveal, chronology, relationship graph, hybrid.
- **Composition:** fixed frame, asymmetric editorial, continuous canvas, modular grid, layered depth, full-bleed scenes, dense index, adaptive composition.
- **Interaction:** reveal, zoom, drag, scrub, hover discovery, keyboard command, progressive disclosure, spatial traversal, timeline scrub, contextual transformation.
- **Time:** static, cinematic pacing, live, evolving, chronological, stateful.
- **Content behavior:** cards, fragments, annotations, chapters, objects, coordinates, scenes, records, clusters.

## Avoid style-label concepts

Bad:

- Minimal concept
- Cinematic concept
- Premium concept
- Brutalist concept

Better:

- A private archive that reveals itself through progressive discovery.
- A living index where relationships between notes become navigation.
- A continuous film-like sequence where scrolling changes the editorial frame.

The second form contains a behavioral proposition, not just an adjective.

## Deliberate divergence

When generating candidates, force at least one candidate to challenge a default assumption:

- What if the homepage is not a homepage?
- What if navigation is not persistent?
- What if search is not a search box?
- What if an article is not a page?
- What if the content itself becomes the navigation?
- What if motion explains structure rather than decorates it?

Do not force novelty when it harms the task. The candidate must still solve the user's problem.

## Presentation

Present candidates in a comparison format that a non-designer can understand:

```text
01 — [concept name]
Mental model: ...
What you experience: ...
Signature interaction: ...
Why it is different: ...
Best for: ...
Trade-off: ...
Reference: ...
```

Avoid requiring the user to understand design vocabulary.

## User choice

Ask the user to react by feeling and preference, not by technical terminology:

- Which one feels most like you?
- Which one would you want to explore?
- Which one is too strange / too quiet / too dense?
- Do you want to combine one concept's interaction with another's visual world?

Capture their response as a Design Decision and preserve the rejected alternatives as context rather than silently deleting them.
