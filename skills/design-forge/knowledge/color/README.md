# Color Knowledge

Color should be reasoned about as a system of relationships and roles, not as a collection of attractive hex values.

## Reasoning chain

```text
Intent
  ↓
Emotional + semantic requirements
  ↓
Color roles and relationships
  ↓
Contrast + hierarchy
  ↓
Palette
  ↓
Semantic tokens
  ↓
Figma variables
```

## Core dimensions

- hue
- saturation / chroma
- lightness / value
- temperature
- contrast
- dominance
- semantic meaning
- surface relationships
- interaction states
- accessibility

## Important rule

A color should have a reason to exist.

Do not add colors merely to make a palette feel complete.

## Color roles

Start with semantic roles rather than raw names:

```text
background
surface
text-primary
text-secondary
border
accent
interactive
success
warning
error
focus
```

The actual palette can then be derived from the visual direction and product requirements.

## Agent behavior

Ask experiential questions:

- Should the interface feel warm or cool?
- Should color quietly support the content or become a major visual event?
- Should actions be immediately obvious through color?
- Should the palette feel restrained or expressive?

Avoid asking users to select hex values unless they already have a brand system.
