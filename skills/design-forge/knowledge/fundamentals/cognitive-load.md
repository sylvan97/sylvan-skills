# Cognitive Load

## Principle

Interfaces should minimize unnecessary mental work so attention can remain on the user's task. Cognitive load is contextual; complexity is not automatically bad when it supports the task.

## Trigger

Activate when a screen has many choices, long onboarding, comparison tasks, complex navigation, or users must remember information between steps.

## Non-designer question

> 用户最需要思考的那一件事是什么？还有哪些信息是在增加负担，而不是帮助完成这件事？

## Decision

Reduce unnecessary memory, choices, context switching, and interpretation. Preserve information that supports the task.

## Specification implications

- Keep primary task visible.
- Prefer recognition over recall.
- Preserve context across steps.
- Use progressive disclosure when secondary complexity is real but not immediately needed.
- Group related controls and information.

## Verification

Observe a critical task without explaining the interface. Record where users pause, backtrack, or ask what to do next.

## Common failures

- hiding essential information in the name of simplicity
- too many equal-priority choices
- forcing users to remember previous screens
- long forms without grouping or progress

## Sources

- John Sweller, Cognitive Load Theory
- Nielsen Norman Group, Recognition and Recall
